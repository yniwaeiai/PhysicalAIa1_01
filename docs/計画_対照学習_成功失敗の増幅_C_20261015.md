# 計画: 腕 C = 同じ配置の成功・失敗ロールアウトで「成功条件付き − 失敗条件付き」の差を増幅する（2026-10-15、research/Fable。結果を見る前に固定）

ユーザの依頼（10/15、research 宛）: 「ハンド傾けは学習でできるようになったが再現性が確率的。同じ基底に対して成功した動作データと失敗した動作データを生成し、対照学習で成功と失敗の僅差を増幅し、潜在空間で正例・負例の分布を明確化したい。実行可能性を検討し、可能なら RunPod で学習・評価」。
本計画は R-a（回復データ v3、計画 v2 §18）と**独立の腕**。線 V1〜V4・評価集合 E1/E2/E3/T・v1 の参照は変えず、同じ物差しに並べる。

## 0. 実行可能性の判定（結論）

**実行可能。ただし「潜在空間の対照」単独ではなく、行動分布の対照として実装する。**

1. 成功・失敗のデータは安く作れる。v1 方策を**同じ seed（= 同じ配置・同じ初期状態）から 8 本**走らせれば、両方の結果が混ざる窓が drawer で大半、k4/k6 で 4 割程度得られる（E1 の v1 成功率 drawer 0.56 / k4 0.88 / k6 0.88）。trace v2 は方策に渡した 128 px の 2 画像・実行行動・状態を毎 step 持つ（`eval_kadai_closedloop.py --trace`）ので、再生なしで学習 HDF5 に変換できる。
2. 潜在表現だけを対照（InfoNCE 型の補助損失）で分けても行動は変わらない、と予測する。確定した原因（計画 v2 §18）は「同一の初期状態 = 同一の表現から、方策の**標本化**で経路が 1〜2 cm 散り（L1a）、前 1/3 の手先位置が成否を運ぶ（I4/I5）。失敗状態でも方策は自信があり（I2）、停留後は戻れない（W）」。表現を分けても (a) t0 の分岐は表現の差ではないので減らず、(b) 失敗側の状態で取るべき矯正行動の手本が教師に無い（それを足すのが R-a）。「ここは失敗側」と分かっても何をするかは別の情報。
3. 行動分布の対照なら、成否を運ぶ量（最初のチャンクの標本と、その後の手先位置）に直接働く。実装は **結果条件付きの流れ + 推論時の負の誘導（classifier-free guidance の負例版）**: 学習時に prompt の末尾へ結果トークン（成功 / 失敗）を付け、推論時に v = v(o, 成功) + w·(v(o, 成功) − v(o, 失敗)) で積分する。w が「僅差の増幅率」で、w = 0 が増幅なし。同じ観測に対する成功条件付き分布と失敗条件付き分布の差を w 倍に広げる = ユーザの「僅差を増幅」を行動の流れ場で行う形。
4. 競技側の前例との違い（`feedback-self-imitation-on-strong-lora-is-negative`）: T2 の dpo1 は条件 145・対 1,962、負け側は分岐後の別の状態、流れの MSE を代理尤度にして β 300〜3,000 で 200 step、held-out の margin が 0 に落ちた（学習対への適合）。本腕は (a) 対でなくラベル条件付け（対の数で過適合しない）、(b) 同じ seed から複数本（配置でラベルが当たる近道を塞ぐ）、(c) 推論側に増幅の用量 w を持つ（用量反応で機構を読める）、(d) 学習前に「前提試験」（§3-3）で分離できたかを閉ループの前に測る。si1（自己模倣 −13/256）の懸念は w = 0 条件が v1 との差として測る。
5. 見送る変種（理由）: InfoNCE 型の補助損失（上 2）、同一状態の対の DPO（t0 の第 1 チャンクだけが同一状態。既存 `--dpo-pairs` 経路で回せるが、僅差のチャンクに対し流れの MSE の雑音が大きく margin の S/N が低い。C の前提試験が通り閉ループが伸びなければ次の候補、§7）、v3 + C の併用（v3 の結果の後）。

## 1. 仮説と、何が分かれば何と読むか

- H-C1（前提）: 同じ配置・同じ初期状態からの成功本と失敗本は、観測と行動の列から区別できる（配置をまたぐ共通の方向は無い（L1b）が、画像に条件づけた非線形の境界はある）。
- H-C2（効果）: 成功条件付き分布と失敗条件付き分布の差を推論時に増幅すると、接近の前 1/3 で手先位置が成功側に寄り、確率的な群の成功率が上がる。
- 読み分け: 前提試験が通り閉ループも伸びる → H-C1・H-C2 支持。前提試験が通り閉ループが伸びない → 分離はできるが行動の矯正にならない（情報は「良し悪し」だけで「どう動くか」が無い = §0-2 の予測どおり）。前提試験が通らない → 僅差は観測から読めない（標本化の運）→ 対照学習の線は閉じ、R-a 側へ。

## 2. 設計

### 2-1 データ（Pod、OSMesa、`--ref-pose`、方策サーバ v1、trace v2）
- 配置: 新規 seed **8000〜8099**（評価 1000〜1047・3000〜3047、較正 2000〜2015、R-a 5000〜5099、E3 6000〜6047・7000〜7047、A' 標的と重ならない）× 3 タスク × **8 本**、摂動 **strong**（不足は強い摂動で起きる）、250 step、replan 5。2,400 本（A' の 168 本/11 分から ≈ 2.7 h）。
- ラベル: **clean 成功**（done ∧ 対象外 ≤ 1 mm）= 成功、それ以外 = 失敗。done ∧ 衝突は失敗側（k4 で多い。内訳を記録）。
- 窓の選抜: 8 本に成功と失敗の**両方**がある窓だけ使う（0/8・8/8 の窓は捨てる = 配置からラベルが当たる近道を塞ぐ）。窓ごとに成功 ≤ 2 本・失敗 ≤ 2 本（seed 順で先頭）。seed 8000〜8079 = 学習、**8080〜8099 = 前提試験の held-out**（学習に入れない）。
- 長さ: 成功本は done まで、失敗本は **先頭 100 step で打ち切る**（停留の開始は中央値 step 44、成否は停留の 20 step 前で決まる（R10）。停留の長い押し当てを「失敗」として大量に入れない）。
- 形式: `kadai_demos_v1` と同じ HDF5（`kadai_record.py` の規約: 画像は env の生の向き = trace の 180° 回転を戻す、state 8 = 位置 3 + 軸角 3 + 指 2、actions 7 = 実行行動 `act_exec`、`category`・`source_demo`・`instruction` の attrs）。**ラベルは instruction の末尾**に付ける（loader `parc/perturbed_dataset.py` は prompt をファイルの attrs から取るので、基底 × ラベルでファイルを分ける: `<base>__succ.hdf5` = `"<instruction> (outcome: success)"`、`<base>__fail.hdf5` = `"<instruction> (outcome: failure)"`）。
- 教師 demo（`kadai_demos_v1`、910 本、79,854 frame）は全部 **成功ラベル**で入れる（instruction を同じ規則で書き換えたコピー）。
- 混合比はフレーム数で確認（教師 80k に対しロールアウト 50〜90k の見込み。超えるなら窓ごとの本数を 1+1 に落として揃える。目標: ロールアウト ≤ 教師）。

### 2-2 学習（v1 と同じレシピ）
`scripts/train_lora_kadai.py`、base = π0.5-LIBERO、rank 16 / α 32 / `--targets attn-mlp` / lr 1e-4 / warmup 200 / batch 16 / seed 0、**2,400 step（主、v1・v3 と同じ）**、snapshot 2,400 と **3,600**（副。データが約 2 倍なので露出が半分になる。前提試験の AUROC が 3,600 で ≥ +0.05 高いときだけ閉ループも測る）。出力 `kadai_c1`。

### 2-3 推論（負の誘導）
`kadai/scripts/serve_policy_cfg.py`（`serve_policy_noise.py` と同じ作り。openpi のソースは変えない）: 要求の `_cfg_w = w` と `_cfg_neg = "<instruction> (outcome: failure)"` を受け、prefix を 2 本（成功 prompt / 失敗 prompt）埋め込み、Euler の各 step で v = v_s + w·(v_s − v_f) を使って同じ初期ノイズから積分。w = 0 は通常の推論と同一（§3 で確認）。行動は通常どおり clip。用量 **w ∈ {0, 1.5, 3}**。

### 2-4 評価（v1 と同時・同条件、seed 対応、250 step、`--ref-pose`、OSMesa、replan 5）
- 用量反応と w* の選定: **E1**（strong 3000〜3047、各タスク 48）と **T**（A' 標的 34 seed × 8）で v1・C(w=0)・C(1.5)・C(3)。w* = E1 drawer+k6 の clean がもっとも高い w（同点は小さい w）。
- 確認（主）: **E3**（strong 7000〜7047・mixed 6000〜6047、各タスク 48）で v1 と C(w*) を seed 対応で。
- 併記: 成功 ep の step、衝突なし、打ち切り、停留の開始 step の分布、接近 step 13 の手先位置の窓内 SD（L1a の物差しで「標本化の散り」が w で減るか）。

## 3. 操作チェック（本判定の前。1 つでも落ちたら止めて親へ）
1. データ: 成功/失敗ファイルの tokenized prompt が異なる（assert）。窓の数・本数・フレーム数（タスク × ラベル）、失敗の内訳（not done / done ∧ 衝突）、打ち切り位置。画像の向き・state・actions の規約が `kadai_demos_v1` と同じ（同じ env 行動を記録した expert demo 1 本と trace を突き合わせ、画素差 0・actions 差 0）。
2. 学習: loss 曲線を v1 と並べる。学習パラメータ数 = v1 と同じ（35.24M）。
3. **前提試験（held-out 窓 8080〜8099、学習前の閉ループより先）**: 各チャンク（10 step 単位）で流れの損失を成功 prompt と失敗 prompt で**同じ (t, ε)** で測り、score = L_fail − L_succ、真のラベルとの AUROC を step の bin（≤ 15 / 16〜40 / > 40）とタスク別に。帰無は窓内でラベルを入れ替えた順列。**線: bin ≤ 15（第 1 チャンク）AUROC ≥ 0.60 かつ bin 16〜40 ≥ 0.70 → 前提通過。第 1 チャンクが ≤ 0.55 かつ 16〜40 も ≤ 0.60 → 前提不通過（閉ループは w=0 と w=1.5 の E1 だけ測って閉じる）。**
4. 誘導: 同じ `_noise_seed` で C(w=0) の行動が通常サーバ（成功 prompt）と一致（|Δ| < 1e-4）。w = 3 の行動の大きさ（|Δ位置| の中央値）が w = 0 の 2 倍を超えない（超えれば w の格子を {0, 0.75, 1.5} に下げる）。‖v_s − v_f‖/‖v_s‖ の step 別中央値を記録（増幅の実効量）。
5. 評価: v1 の E1 が過去の値（drawer 27 / k4 42 / k6 42 / 48）の ±4 以内（物差しの連続性。pos0 固定で変わりうるので記録）。

## 4. 線（結果の前に固定。主は C1）
| # | 指標 | 支持 | 反証 | 保留 |
|---|---|---|---|---|
| C1 主 | E3 の drawer + k6 の clean（プール 192 本、strong + mixed）: C(w*) − v1 | ≥ +0.10 | ≤ +0.03 | その間 |
| C2 機構 | T の運群 8 seed の seed 対応差 C(w*) − v1 | ≥ +0.15 | ≤ +0.05 | その間 |
| C3 用量反応 | E1 drawer+k6 の clean が w = 0 → 1.5 → 3 で単調非減少、かつ C(1.5) − C(0) ≥ +0.05 | 両方 | C(3) ≤ C(0) | その間 |
| C4 退行なし | E3 の各タスクの clean: C(w*) − v1 | 全タスク > −0.06 | いずれか ≤ −0.06 | |
| C5 自己模倣の害（対照） | E1 の C(0) − v1（増幅なし = ラベル付きの自己ロールアウトを足しただけ） | ≥ −0.03 | ≤ −0.08（データを足すだけで損なう = si1 の再現） | その間 |
- 区間は seed 単位。V3 と同じく成功未観測 7 seed の |Δ| ≤ 0.05 を補助報告（配置群には効かないはず）。
- 事前の分岐: C1 支持 ∧ C3 支持 → 「行動分布の対照（負の誘導）で確率的な群が改善」。C1 支持 ∧ C3 反証（w に依らず上がる）→ 効いたのはラベル付きデータの追加で増幅ではない（自己模倣の正の効果。si1 と逆の結果なので描画差 OSMesa の混入を疑い v3c 相当の対照が要る）。C1 反証 ∧ 前提通過 → §1 の「良し悪しは読めるが矯正にならない」。C1 反証 ∧ 前提不通過 → 対照学習の線を閉じる。

## 5. 予測（research、結果の前）
- 前提試験: 第 1 チャンク AUROC 0.55〜0.65（境界）、16〜40 で 0.70〜0.80（手先位置の差が画像に出る）。通過の確率 6 割。
- C1 を超える確率 **2 割**。C5 は −0.03〜0（w=0 は v1 とほぼ同じ。si1 ほど落ちないのは教師が 50% 以上残るため）。C3: w = 1.5 で +0.03〜+0.06、w = 3 で行動が荒れて k4 の衝突が増える（C4 を k4 で割る可能性 3 割）。
- 伸びる場合の別仮説（切れないもの）: データの追加・OSMesa 描画の一致（学習と評価が同じ描画になる = v3c と同じ交絡）。C3 の用量反応が「増幅」の寄与を切り分ける唯一の手がかりで、w=0 条件が描画・データ追加の分を担う。

## 6. 計算と日程・Pod の運用
- Pod は kadai セッション（`kadai-l40s-3`）が R-a の収集 → v3 学習（≈ 3.5 h）→ 評価に使用中。**二重操作を避け、C の起動はその空きに直列で入れる**（調整は research ↔ kadai セッションの SendMessage）。空きが 12 h 以上先なら、学習・ロールアウト用に 2 本目の Pod（L40S、EU-NL-1、環境は 10/13〜14 の手順）を立てる（コスト ≈ $1.09/h × 12 h）。
- 見積もり: ロールアウト 2.7 h（CPU 主体、GPU は方策サーバのみ → v3 の学習と並走可）、変換 10 分、学習 3.5 h（2,400）+ 1.7 h（3,600）、前提試験 20 分、評価 E1+T × 4 条件 ≈ 1,660 本 ≈ 2 h、E3 × 2 条件 576 本 ≈ 40 分。合計 ≈ 10〜12 h。
- 実装（Sonnet のサブエージェント、research が監査）: `kadai/scripts/build_contrast_dataset.py`（trace → HDF5 + 混合比の表）、`serve_policy_cfg.py`、`premise_auroc.py`、`pod_run_contrast_{rollouts,train,eval}.sh`。CPU で済む検査は手元の `kadai/state/trace_aprime/` で先に通す。

## 7. 条件付きの次
- 前提通過 ∧ C1 反証 → 同一状態（第 1 チャンク）の対で DPO（既存 `--dpo-pairs`、対ごとに同じ (t, ε) で margin の雑音を落とす）を 1 本。
