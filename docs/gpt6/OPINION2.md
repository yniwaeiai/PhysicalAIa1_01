v3 は次に試す価値が高い。ただし「確率的失敗の原因を共変量シフトと確定」「配置群は教師を直さない限り救えない」という二つの断定には反対する。現状で強いのは、接近中のロボット状態への介入で継続成功率が変わり、方策の失敗軌跡上にも expert が完遂できる状態がある、という結論である。以下、計画＝docs/01_plan_v2.md、履歴＝docs/02_work_history.md と略す。指定の集計・前回意見と関連コードを読んだ。生 trace、教師データ、解析スクリプト、Dataset 本体、expert 生成器本体は提供されておらず読めない。実験・学習・評価・コード変更は行っていない。

I4/I5 と L1b は矛盾しない。前者は特定配置の特定状態を変える介入、後者は配置を跨ぐ共通の線形方向の予測試験である。配置ごとに有利な方向が逆でも両立し、非線形な幾何、接近の進捗、画像による行動変化でも説明できる。「単純な幾何ではない」は広すぎ、「この座標・時刻・共通射影では説明できなかった」とする。drawer は done の AUROC 0.560 に対し clean では 0.679 であり、v3 の主要指標に対応する信号を捨ててはいけない（docs/12_lanes.md、L1b）。LOWO は同 seed の別窓を学習側に残すため、一般化評価には seed 単位の除外が必要である。

I5 の名称には実装とのずれがある。(pp) は回転を固定せず、失敗側から中央値 3.56°変わる。(po) も位置を固定せず約19 mm動く（docs/11_branches_i5.md「操作チェック」；code/branch_kadai.py、ik_arm）。したがって「位置を目標とした IK 介入で効果をほぼ再現」が適切で、位置だけの純粋効果ではない。R19 は no-op なので冗長自由度一般の無効性を検証していない。s/3 の I4 は固定具が同じという設計上の制約があり、2s/3 の小さい差も等価性の証明ではない。さらに k4 の (pp)−(a) はゼロであり、全タスクへの一括した断定は避ける（同ファイル「最終成功率」；計画§16）。位置変更は視覚入力と機械的条件を同時に変えるので、知覚・模倣・制御のどこが逸脱を生むかは未分離である。

「漸進的に決まる」も留保が要る。I3 の p(t) は最終的に失敗した軌跡を選び、その途中から分岐した条件付き確率である（docs/08_branches_i3.md「p(t)」）。失敗で条件付ければ、後半ほど低い値の状態が選ばれやすい。これは失敗軌跡上の悪化を示すが、全 rollout が時間とともに悪化する証拠でも、各軌跡が連続的に悪化する証拠でもない。異なる時点の急落を平均しても滑らかな低下になる。L1b の確率的ラベルによる識別限界は重要だが、「p が一定範囲なら AUROC の天井は約0.65」と範囲だけからは決まらない。p の分布と状態の重みが要る。反復から推定した p 自体との対応を補助指標にしたい。

共変量シフトは有力な作業仮説だが、L1d は証明として弱い。「教師 SD <1 mm」は drawer/k4 の z 軸であり、k6 の z は4.7 mm、教師の他軸には数十 mmの幅がある（docs/12_lanes.md、L1d）。決定的 expert でも配置を混ぜた分散はゼロにならない。ほぼ特異な共分散による距離の飽和と、同 step の速度差を、学習状態全体の支持域外と同一視すべきでない。当初予定の対象距離・局面を揃えた比較に戻し、配置差を条件付け、教師経路への横方向のずれと進捗の遅れを分けたい。成功も教師から離れているので、逸脱は失敗の十分条件ではない。

同一初期状態からのばらつきは方策サンプリング由来という読みと整合する。一方、平均のずれはサンプリングの分散だけでは説明できない。非線形な閉ループ応答、行動の系統誤差、チャンク実行、描画差、時刻対応が候補である。初期の教師状態でも平均指令がずれるのか、逸脱後に補正できなくなるのかを分けると、最初の誤差とその増幅を混同せずに済む。現資料では寄与率は読めない。「共変量シフト」はこの増幅過程の説明として使い、単独の根本原因名にはしない。

配置群の expert 失敗は観測事実だが、「構成上学習分布に無い」は飛躍である。生成時と評価時の環境・初期状態が一致し、その近傍でも成功教師が無いことが必要だ。I6 は ref で成功未観測0/7、中間0/5だが、tr0 では各1件成功し、較正でも生成時と評価時の成功率が一致しない（docs/13_expert_eval.md「操作チェック1」「(i)」）。有限標本から連続配置の支持域の穴は確定できない。中間群も「この expert・環境・予算で失敗する条件に方策の成功がある」までで、教師一般を超えた汎化とはまだいえない。

「中間群は回復データで救えない」には直接反例の芽がある。I6 の中間群は失敗側から clean 0.133、成功側から0.333であり、初期状態から失敗する expert も、方策の prefix と組み合わせれば完遂する場合がある（同「(ii) 群別」）。配置の能力限界と、その配置内の回復可能状態は別である。配置群を範囲外にするのは研究資源の判断として妥当だが、expert 改良の論理的必須性ではない。

I6 の回復率の近さも等価性ではない。組平均差−0.071に対して seed 平均差は−0.024、k6 は組平均−0.188で、集約で印象が変わる。実走行は失敗側21・成功側25状態で、同じ状態を組へ複製している（同「(ii)」）。独立性を28組と見積もらず、seed を単位に不確実性を示すべきだ。復元時点の対象外物体の移動も記録されているため、clean の基準は suffix 開始時にリセットせず、元エピソードから引き継ぐ。expert の残り時間も方策と揃える必要がある。code/run_expert_eval.py の episode は t_off を結果へ記録するだけで、ループの max_t から差し引いていない。

v3 収集では固定時刻の点に加え、初接触直前までの遅い接近状態を少量確保する案を優先する。現案の t≤25 だけで十分とはいえず、接触力ゼロは「過去にも接触していない」を意味しない（計画§18）。時刻、対象距離、接触履歴、expert の受理率を残す。停止時刻からの逆算は診断用には使えても、本番で未来情報を要する検出器とは区別する。接触後への拡張は先頭局面への再初期化の適合性を別に確かめてからでよい。

suffix の先頭には方策が実際に訪れた状態への expert ラベルがあるので、prefix 全体を含めないこと自体は欠陥ではない。ただし、少数の開始状態しか直接監督せず、その後は expert が訪れる状態が大半になる。成功のみ受理すると難しい逸脱が再び脱落する。由来別・時刻別の試行数と受理数、回復開始付近の学習比率を固定し、同じ rollout の近接分岐による後半の重複を抑える。単なる本数上限より、配置と局面の被覆を優先したい。これは成功選別付きの単回データ集約であり、学習方策の訪問状態を反復して監督する DAgger と同等とは主張しない。

混合比は demo 本数比では決まらない。学習コードの通常経路は Dataset の index を shuffle するが、その本体は未提供である（code/train_lora_kadai.py、main のデータ構築）。元データ／回復、タスク、局面、開始付近それぞれの実サンプル数と露出率を確認したい。同じ2,400 step は計算量を揃える比較であって学習到達度を揃えない（計画§18）。v2 は描画・局面・長さ・配置構成まで一致したデータ量対照ではない。まず v3 と対照の予算・初期重み・前処理を揃え、未使用 seed の元状態／回復状態で学習不足と分布不足を分ける。学習集合を代用する検証損失は汎化の証拠にならない（同コード）。

v3c は結論に必要である。初期状態からの OSMesa demo を同数足すだけでは、長さや局面、成功受理される配置が違う。可能なら共通して受理できる配置で時刻・学習フレーム量を揃え、対応不能な範囲は明示する。同一状態の EGL/OSMesa 描画が可能なら、描画だけの効果をさらに直接比較できる。低予算ならまず v3 を回す順序はよいが、v3c の設計は今固定し、V1 だけでなく V2 に改善が出た場合も機構を主張する前に実施する。v3 が無効でも、描画の利益とデータ混合の害が相殺した可能性があるため、原因仮説を無条件に温存するのも適切でない。

V1〜V4 は既定の実用効果の線として残し、統計的な確定と分ける（計画§18）。E1 の改善余地は「改善可能な配置の割合×その群の残余失敗率」に制約されるが、その割合は未測定であり、反証後に天井で説明しない。全体差に加え、方策結果を見る前に定義した expert 可否別の差を補助報告する。V2 の「運群＝expert可能」も clean では全件でない（docs/13_expert_eval.md「(i)」）。V3 は真の負の対照ではなく、近隣配置への汎化や prefix と expert の組合せでも改善しうる。小さい点推定は無効果の証明にならない。V4 も非劣性を主張するなら区間下限が許容限界を上回る必要がある。

v1 の同条件再評価は必須で、計画の同時比較を維持する。pos0・完全初期状態・時間予算を揃え、seed 対応差とその区間、タスク別内訳を出す。seed 対応は推論乱数の対応を保証しない。群は過去ラベルのまま固定し、v3 の結果で再分類しない。選抜からの平均への回帰は新しい v1 との差で扱う。反復や窓の数を独立 seed 数として数えず、探索に繰り返し使った評価集合とは別の未使用 seed で確認する。W の運群基準の上昇も、pos0 変更と平均への回帰の寄与を分離できていない（履歴§34）。

代案の順位は、実訪問状態からの回復データ、誤差に合わせた DART 型の expert ノイズ、更新方策での追加集約、接近の正則化・経路多様化とする。現状は分岐基盤があるので回復データが最も直接的である。DART 型は方策 rollout を減らせるが、等方的ノイズより実測の方向・時間相関に合わせ、攪乱後の状態への無ノイズ expert 行動を教師にする。反復集約は更新後に残った未被覆状態が確認できた場合に絞る。正則化は平均経路が悪ければ失敗を安定化し、多様化は成功可能な経路を増やす根拠が必要になる。W の不利は実測だが、平均化と null-space はそれぞれ間接的根拠と no-op による優先度低下であり、一般的無効性の実証とは書かない。

前回の測定修正・局所介入・成功経路での誤発火確認は進んだ。一方、支持域の検証と環境同一性は残った（docs/00_opinion1.md）。最小限の追加証拠は、局面・配置を揃えた訪問分布の差、未使用状態での回復区間の学習確認、描画と学習予算を揃えた v3 対 v3c の閉ループ改善である。改善とともに、逸脱後の成功率上昇または停留への移行減少を示せれば、「訪問分布のずれが失敗に寄与し、回復データで軽減した」と主張できる。全失敗の唯一原因、教師の絶対的能力限界、任意配置への一般化までは主張できない。
