# 計画: 確率的失敗の原因追究（2026-10-14、実行前に固定）

提出物の作成は終了済み（ユーザ 10/14）。以後は研究として原因を特定し、可能なら対処する。

## 0. 問いと現状の整理

最終評価（v1、各タスク 48 本）で失敗が出る。同じ初期条件の再実行で、失敗は運（p≥0.5）・決定的（p=0、全て強い摂動）・中間に分かれる（§18）。
**未検証**: 「停留」の中身。観測は「手先がほとんど動かない」までで、(i) 方策が止まる行動を出している、(ii) 動く行動を出すが物理的に動けない、(iii) 迷って行動が打ち消し合う、を区別できていない。

## 1. 実験 A（停留の中身）— 本計画で固定する範囲

### 1.1 データ
- 既存の失敗 seed 30 本（drawer 7・K4 3・K6 20。§18.2 と同じ）を、無摂動の方策（v1 LoRA、replan 5、OSMesa、T0 条件）で **8 反復**、`--trace` つきで再実行する。成功・失敗の両方の軌跡が同じ seed から得られる。
- 記録: 毎 step の生の行動と実行した行動、手先位置・姿勢、関節角・速度、関節限界までの余裕（rad）、ロボットが触れている物体名、各推論の行動チャンク全体。
- 追加で、最終評価の失敗を除いた**成功 seed**（各タスク 10 本 × 1 反復）を対照として記録する。

### 1.2 ★操作チェック（本実行の前）
1. 煙検査: 1 エピソードで trace の各配列の形と値の範囲を確認（act_raw が [-1,1]、jmargin ≥ 0、contact が空でない step が接触局面で存在）。
2. 再現性: 反復全体の成功率が §18.2 の T0（drawer 55%、K4 88%、K6 50%）から**±15pt 以内**。外れたら環境が違う（描画・seed）として原因を調べてから進む。
3. 記録の無害性: `--trace` あり/なしで同じ seed・同じ rep の結果（成功・steps）が一致すること（5 本）。一致しなければ trace が挙動を変えている。

### 1.3 定義（事前固定）
- **終端の停留**: 失敗エピソード（max_steps=250 まで未達）の最後の 40 step で、手先の移動距離の合計 < 2 cm。それ以外の失敗は「停留でない失敗」として別集計。
- 停留区間の統計量（最後の 40 step）:
  - `a_pos` = 生の行動の位置 3 成分の大きさ（ノルム）の中央値。基準値 `a_ref` = 同じタスクの成功エピソードの、動いている step（手先速度が上位半分）での `a_pos` の中央値。
  - `a_rot` = 同様に回転 3 成分。
  - `dither` = 連続する生の行動の位置方向のコサインが負になる割合。
  - `jm` = 関節限界までの最小余裕（rad、全関節・区間内の最小）。
  - `contact` = 区間内で最も多く触れている非ロボット物体。
- **分類**（排他、この順に判定）:
  1. 関節限界: `jm` < 0.05 rad。
  2. 物理的な詰まり: `a_pos` ≥ 0.5·`a_ref`（動こうとしている）かつ手先が動かない、かつ（1 でない）。サブ分類は `contact`（取っ手・扉など対象物か、対象外物体か、接触なし＝特異点・制御の飽和）。
  3. 方策の静止: `a_pos` < 0.25·`a_ref`。
  4. 迷い: `dither` > 0.3 かつ上記以外。
  5. 未分類。

### 1.4 予測（結果を見る前）
| # | 予測 | 反証される条件 |
|---|---|---|
| P1 | p=0 の seed（強い摂動）の失敗は、関節限界または物理的な詰まりが過半（≥60%） | 方策の静止＋迷いが過半 |
| P2 | 運の失敗（p≥0.5 の seed の失敗）は、方策の静止または迷いが過半（≥60%） | 詰まり・関節限界が過半 |
| P3 | 手首の傾きが 85° 以上の停留は、関節限界または詰まりに偏る（K6 の 1014 型） | 傾きと分類が独立 |
| P4 | 同一 seed の成功と失敗の行動は、最初の分岐が全体の前半（step の 40% 以内）にある | 分岐が停留直前に集中 |
| P5 | 失敗の「迷い」は行動チャンクの境界（5 step 周期）で生じ、チャンク内では整合している | 周期性なし |

P1 と P2 が両方外れた場合、「運/決定的」の分類が原因の区別に対応しないことになり、問いの立て方から見直す。

### 1.5 判断（A の結果→次の一手）
- 方策の静止が主因なら: 停留のデモ上の根拠を調べる（人間デモの静止区間が混入しているか。`kadai/state` のデモ統計）→ 学習側（静止区間の除去・重み）。
- 詰まりが主因なら: 実験 B（停留点でシミュレータ状態を保存し expert に引き継ぐ。回復すれば方策側、しなければ状態が詰んでいる）。関節限界なら手首傾きの上限や初期姿勢の扱い。
- 迷い・分岐が主因なら: 実験 C（分岐点の特定）→ 推論側の対処。
